Good morning everyone.

Let me start with a simple question. If we are looking for a new medicine, how can we find a molecule that is similar to a useful one, without checking every molecule in a huge database one by one?

This is the problem behind my research. My topic is machine learning for graph similarity search.

A graph is just a way to represent objects and relationships. For example, a molecule can be shown as atoms connected by bonds. A social network can be shown as people connected by relationships. A software program can also be represented as connected structures.

In many situations, we do not need an exact copy. We need something similar enough to be useful. The challenge is that measuring similarity between graphs can be very slow when the database is large. Accurate checking is important, but checking everything one by one is like asking a librarian to open every book in a library before finding the right one.

My research asks how we can make this search smarter.

The main idea is to combine machine learning with smart indexing. Machine learning can help the system estimate which graphs are likely to be close to the query. Indexing can help the system know where to search first. Together, they can narrow a huge database into a smaller set of promising candidates.

You can think of it as a smart librarian. Instead of walking through every shelf, the librarian first understands what kind of book you need, goes to the most relevant shelves, and then checks the best books carefully. In my research, machine learning helps with the first guess, and indexing helps organize the search.

This matters because current methods often improve only one part of the problem. Some methods make filtering faster, but may miss useful matches. Some methods estimate similarity quickly, but are not always tested as part of a full search system. My aim is to study how these parts can work together in one more complete framework.

The expected contribution is a search system that is faster, more scalable, and still reliable. In simple words, I want the system to save time without missing the important matches.

This research can support real applications. In drug discovery, it may help researchers find molecules with similar structures more efficiently. In biology and network analysis, it may help compare complex structures. In software analysis, it may help detect similar program patterns in large code collections.

So the main message of my 3MT is this: better graph similarity search is not only about building a faster model. It is about building a smarter whole search system, one that knows where to look first and then checks carefully.

Thank you for listening.
