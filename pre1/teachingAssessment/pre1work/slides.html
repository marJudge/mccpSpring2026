When “close enough” matters
Query graph → Database of graphs → Similar graphs
Like finding molecules or proteins that are similar to a query—not identical.

The bottleneck: how many edits to turn one graph into another?

The previous best method hit a wall
  • State-of-the-art (AStar-LSa) is fast but memory-hungry
  • When graphs get bigger or the allowed distance gets larger → runs out of memory
  • Limits real-world use (e.g. large chemical or protein databases)

Graph size / threshold ↑ → memory ↑ → out of memory

Smarter search, less memory
  • New tighter lower-bound estimate → prune more bad options earlier
  • Formally proved tighter than the previous method
  • Efficient algorithms to compute it → faster overall
Like a better map that tells you earlier when a path is a dead-end.
Result: faster and lighter
  • AStar-BMao = new algorithm using the new bound
  • Faster than AStar-LSa on real datasets
  • Much less memory → scales to larger graphs and larger thresholds
  • Where AStar-LSa runs out of memory, AStar-BMao still finishes
